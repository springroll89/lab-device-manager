# 局域网与平板部署

## 运行方式

系统只需要安装在一台长期运行的实验室电脑上。设备串口、SQLite
数据库和采集服务都在这台电脑；平板与其他 PC 只通过浏览器访问，不安装
单独 App。

1. 给服务器电脑设置固定局域网地址或固定主机名。
2. 在 `config.local.toml` 中设置：

   ```toml
   web_host = "0.0.0.0"
   web_port = 7800
   public_base_url = "https://lab-device.example.lan:7800"
   tls_certfile = "/绝对路径/lab-device.crt"
   tls_keyfile = "/绝对路径/lab-device.key"
   ```

3. 证书必须由公司内部 CA 或其他被平板信任的 CA 签发，并包含
   `public_base_url` 使用的主机名。自签名证书只有在每台平板已安装并信任
   根证书后才能使用。
4. 允许实验室局域网访问服务器的 TCP 7800 端口，不允许从互联网访问。
5. 启动 `python -m lab_device_manager`，平板打开
   `https://lab-device.example.lan:7800`。

`tls_certfile` 与 `tls_keyfile` 必须同时配置。只做临时桌面验证时可以不配
HTTPS，使用 `http://服务器局域网IP:7800`；但移动浏览器在普通 HTTP 页面
通常禁止调用摄像头，因此正式扫码必须使用受信任的 HTTPS。

## 二维码内容

实验实物标签使用 UTF-8 离线文本，例如：

```text
PURICORE实验实物
类型：最终成品
名称：CEM 功能膜成品
编号：20260725-CEM-02-FP-01
批次：20260725-CEM-02
状态：已完成
生成：2026-07-25 00:23
实验人：admin
```

二维码不包含网址，也不依赖服务器 IP。普通扫码工具可直接显示这些基本
信息；系统内扫码会提取“编号”字段并查询当前记录。旧版 `/scan/编号`
网址二维码仍可由系统识别。

## 多端数据互通

所有账号连接同一台服务器、同一个数据库和同一个设备采集引擎。操作员在
平板打标后，实验室主管 PC 的批次页面会通过持续事件流接收设备状态，并用
记录版本检测步骤、偏差、粘度和追溯事件变化，通常在 1–2 秒内更新。

账号只表示“谁在操作”，不是实验容器。一个操作员可以同时负责多个进行中
批次：

- “进行中实验”显示该账号负责的所有批次；主管可看全部批次。
- 扫描批次、中间品或成品标签可直接进入对应批次。
- 搅拌器和注射泵按批次排他占用，同一设备不能同时进入两个批次。
- 注射泵完成加酸后自动释放，搅拌器完成降温后自动释放。
- 粘度计使用独立工位和 5 分钟短租约；扫描待测样品后才把读数路由到该
  批次，记录完成即释放给下一份样品。

## 现场验收

- 用平板、主管 PC 分别登录不同账号，同时打开同一批次，验证步骤变化。
- 用两批实验尝试选择同一台搅拌器，确认第二批得到明确的占用提示。
- 打印一个批次标签和一个原材料标签，分别用 iPhone 系统相机、网页扫码
  和扫码枪验证。
- 断开平板 Wi-Fi 后打一个标，再恢复网络，确认离线队列自动补传且没有
  重复事件。
- 重启服务器，确认账号、批次、库存和追溯事件仍在；按实验室制度备份
  `data/lab_device_manager.db` 和标签/证书配置。
