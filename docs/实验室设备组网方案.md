# 实验室设备数据采集 · 组网方案

> 状态：方案设计（待采购与部署）　·　日期：2026-06-30　·　关联：注射泵/搅拌器/粘度计 的 phase-1 采集软件

---

## 1. 背景与现状

### 1.1 场景
- 所属公司从事**化学**领域，目前聚焦**陶瓷膜的研发与生产（现阶段以研发为主）**；通风柜里的设备基本都是化学/实验室仪器。
- 一个**实验室**，里面排布着多个**通风柜**。
- 各个通风柜里会**摆放各种仪器设备**（数量与类型会随研发/测试任务持续增加）。
- 每个通风柜都已经**预留了一个网口（网线口）**，网线已经敷设到位。
- **机房就在实验室隔壁**。
- 目标：把**所有设备的数据采集下来**（第一阶段：实时读取与记录），并在后续**对设备下发指令控制**（第二阶段：写/操控）。

### 1.2 现实约束
- **研发数据宝贵**：实验数据要可靠采集、可追溯、能复现，需要留存与备份。
- 现场使用人员技术水平一般，**部署与运维要尽量简单**。
- 设备**会越来越多**，方案必须能持续扩展，不能每加一台就重构。

### 1.3 现有设备清单（三台，已完成真机链路验证）

| 设备 | 通信协议 | 物理层 | 关键参数 | 软件状态 |
|---|---|---|---|---|
| 注射泵 Leadfluid TYD02 | Modbus RTU | **RS485**（DB15） | 9600 8E1，地址 1 | 全链路已验证，参数变化可在 Mac 实时监控 |
| 搅拌器 HMS-C（上海小聪） | Modbus RTU（保持寄存器 40001 系） | **RS485**（DB9） | 9600 8N1；出厂地址 `Ad=1` | 单机链路已真机验证 |
| 粘度计 方瑞 LVDV-2T | **自定义二进制流**（非 Modbus） | **RS232** | 9600 8N1；五个字段缩放与累加校验已确认 | USB 直连和 UT-6804 全链路均已验证 |

> 物理层要点：泵与搅拌器都是 **RS485**（可挂多机总线）；粘度计是 **RS232**（点对点，必须独占一路），且为自定义推流协议、无地址。

> HMS-C 地址规则：每台原出厂地址均为 `Ad=1`。只有设备共用同一条 RS-485 总线时才需要改成互不重复的地址（例如 `Ad=1`、`Ad=2`）；地址重复会造成响应冲突，可能导致同一总线上的设备全部无法显示或采集。分别占用 UT-6804 独立串口时，各设备可以继续使用 `Ad=1`。

### 1.4 软件现状
- 已有一套**只读**采集软件，架构按 `InstrumentAdapter` 接口实现注射泵、搅拌器、粘度计和温湿度控制器的独立适配器。
- 传输层同时支持本地 USB 串口和串口服务器透明 TCP；TCP 断线后会在后续采样周期自动重连。
- 多台设备可按不同的 `host + tcp_port` 并行采集。设备看板将网关连接、仪器响应、数据新鲜度与仪器运行状态分开显示。
- TYD02、HMS-C 和 LVDV-2T 均已通过 UT-6804、UT-6408 到 Mac 完成真机通讯验证；应用保持只读采集。

### 1.5 组网思路的演进（为什么走到当前方案）
1. **最初**：485 直接接一台电脑（一个 USB-RS485 转换器）。一两台够用，但**设备一多就不行**。
2. **加转换器**：现有的宇泰 UT-885（RS485）能给 RS485 设备用，但仍是一台电脑插一个转换器的思路，**不可扩展、且设备分散在各柜够不着**。
3. **串口服务器（terminal server）**：设备插串口服务器、电脑经网络访问——「一步到位」。
4. **结合本场景细化**：既然**每个通风柜都已预留网口、设备分散、机房在隔壁**，最优解不是「机房放一个大 8 口串口服务器」（那样还得把各柜串口线拉回机房），而是 **每个通风柜放一个小串口服务器，柜间走现成网线，机房用一台工业网管交换机汇聚**。

## 2. 推荐组网：每柜一个串口服务器 + 机房网管交换机

```
通风柜A                       通风柜B                       ...
[泵+搅拌器 → RS485 总线]       [若干设备]
[粘度计等 RS232 设备]          [...]
     │ 柜内短串口线                │
[串口服务器 A]                 [串口服务器 B]     ← 每柜一个，DIN 导轨，2–4 口混合 RS232/RS485
     │ RJ45                        │ RJ45
  (柜内预留网口)                (柜内预留网口)
     └────────── 现有网线(Cat6) ──────────┘
                      │
        [机房：工业网管交换机]                  ← 汇聚 + VLAN 隔离 + 监控
                      │
        [机房：采集服务器]                      ← 跑采集软件（多设备 + TCP），24×7
                      │
              [NAS / 备份]                      ← 数据留存/备份
```

**核心思想**：串口线**只在柜内**（短=稳、不怕干扰）；柜与柜之间走**已经敷好的网线**；机房统一汇聚、存储、备份。

---

## 3. 为什么是它（方案对比）

| 方案 | 是否推荐 | 原因 |
|---|---|---|
| 长距离 485 拉回机房 | ❌ | 已有网线，不必再拉串口线；长串口线怕干扰、难维护 |
| USB 转换器堆在一台电脑 | ❌ | 设备分散在各柜够不着；USB 走不远；口数有限 |
| **每柜一个串口服务器**（本方案） | ✅ | 串口线只在柜内；柜间走现成网线；扩柜=加一个服务器插网口；故障互相隔离 |
| 机房一个 8 口大服务器 | △ 凑合 | 又得把各柜串口线拉回机房，浪费已敷的网线 |

## 4. 各类设备的角色（对应宇泰店里的品类）

| 品类 | 作用 | 本方案是否需要 |
|---|---|---|
| **接口转换器**（USB 转串口等） | 电脑直连单台 | 规模化后**不再用**（仅调试时临时用） |
| **串口服务器**（接网口的设备，如 MOXA NPort） | 串口 ↔ 网线 桥接 | ✅ **每柜一个，核心件** |
| **工业交换机** | 网线汇聚骨干 | ✅ 机房放一台**网管型**（VLAN、可监控） |
| **光纤转换器** | 网线/串口 ↔ 光纤 | △ 多半**用不上**，见第 5 节 |

---

## 5. 光纤要不要？结论：多半不用

光纤的价值在于：**超长距离（>100m）、强电磁干扰免疫、电气隔离、防窃听**。

本场景：机房在**隔壁**、距离短、普通实验室环境 → **光纤属于超规格**。用**工业级屏蔽 Cat6（STP）**完全够用。

**只在以下「特定那一根」出问题时才上光纤**：
- 某个柜特别远（接近或超过 100m 网线极限）；
- 旁边有大电机/变频器等**强电磁干扰**源；
- 需要**电气隔离**（地环路、高压区）。

原则：**光纤是用来点对点解决「某一段」的，不是用来取代日常网线的，不要全柜光纤（白花钱）。**

## 6. 设备选型清单

| 角色 | 选型建议 | 数量 |
|---|---|---|
| **每柜串口服务器** | 2–4 口、混合 RS232/RS485、DIN 导轨、raw TCP 模式。标杆 **MOXA NPort**（如 5232/5250 双口，按柜内设备数选）；**宇泰**性价比款 | 每柜 1 台 |
| **机房网管交换机** | 8–16 口**网管型**（**MOXA EDS** / 宇泰），支持 VLAN、SNMP，可上 UPS | 1 台（柜多则级联） |
| **采集服务器** | 机房放一台**小工控机或 1U 服务器**，24×7 跑采集软件（不要用个人 Mac 长开） | 1 台 |
| **NAS / 备份** | 群晖等，RAID，定期/异地备份 | 1 台 |
| **网线** | 工业级**屏蔽 Cat6（STP）**，工业 RJ45 接头 | 按柜数 |

> 串口服务器**每口参数（波特率/校验/停止位）在 Web 后台按设备设好**；模式选 **raw TCP**（每口对应一个 TCP 端口，如 `192.168.x.x:4001`）。**不要装厂家的虚拟串口驱动**——raw TCP 免驱、最干净。

## 7. 柜内接线要点

- **RS485 多机总线**：同一个柜里的 RS485 Modbus 设备（如泵+搅拌器）**并到一条总线**，占串口服务器的**一个 RS485 口**；每台设**不同 Modbus 地址**；总线上所有设备**波特率/校验必须一致**。
  - 若两台参数凑不齐（如一台只能 8E1、另一台只能 8N1），则各占一口。
- **RS232 点对点**：RS232 设备（粘度计等）**各占一个独立口**，不能并。
- **常见坑**：
  - RS485 的 **A/B 两线**不同厂家标注可能相反；通信不通时**先对调 A/B**。
  - 自定义协议且无地址的设备（粘度计）即使转 RS485 也**无法多机并**，必须独占一路。
- **规模化时注意**：RS485 总线建议**手拉手（daisy-chain）布线**、两端加 **120Ω 终端电阻**、做好**屏蔽接地**。

## 8. Phase 1（读取）与 Phase 2（控制）

- **同一条路双向**：采集软件经 TCP → 串口服务器 → 串口，既读也能写。Phase 2 下发控制不需要另起网络。
- **Modbus 主站**：采集服务器作为**唯一 Modbus 主站**，按地址轮询各从机；避免多主冲突。
- **自定义协议设备**（粘度计）：独占一路，软件按流解析。
- **软件现状**：`TcpTransport`、设备清单、并行轮询、自动重连和分层通讯状态已经实现。Phase 2 写操作仍未开放；未来如需控制，必须增加**二次确认 + 审计日志**。

---

## 9. 可靠性与数据留存

- **VLAN 隔离**：仪表网与办公网分离（安全 + 可追溯）。
- **UPS**：给工业交换机、串口服务器、采集服务器供电，防断电丢数据。
- **单主站**：一个采集服务器当 Modbus 主站，避免总线冲突。
- **数据集中**：全部落到机房采集服务器 → NAS，再**定期 + 异地备份**。
- **采集服务器 24×7**：机房常开，不用人盯着 Mac。
- **可扩展到 MES/SCADA**：数据都汇总在机房一台服务器，以后对接质量/MES 系统容易。

## 10. 会影响选型微调的几个变量（待确认）

1. **每个通风柜典型多少台设备、什么类型** → 决定每柜串口服务器几口、要不要柜内小交换机。
2. **对停机是否敏感** → 研发验证一般不需环网冗余；若要高可用，交换机上做环形冗余（如 MOXA Turbo Ring / ITU-T G.8032 ERPS）。
3. **柜内环境**（腐蚀性气体/湿度）→ 选防护等级合适的工业件，安装位置尽量在柜外或弱电箱内。
