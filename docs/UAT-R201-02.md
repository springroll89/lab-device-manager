# UAT-R201-02 温度通道与陈化检查点

## 目标

验证系统只使用明确绑定的物理通道判断到温与陈化检查点，不把 WHD46-33 三通道平均值误当反应温度。

## 固定数据

- WHD46-33 CH1：20.0 ℃。
- WHD46-33 CH2：39.0、40.0、41.0 ℃。
- WHD46-33 CH3：80.0 ℃。
- 顶层平均温度故意设为 99.9 ℃。
- 批次反应温度范围：38–42 ℃。
- 到温连续样本数：3。
- 陈化检查点间隔：20 min。

## 执行

1. 在 R201-40 把 `reaction_temp` 绑定到 `ch2_temp_c` / 通道 2。
2. 写入固定数据并触发 `/evaluate-telemetry`。
3. 确认到温事件的 `metric_key=ch2_temp_c`、值为 41.0 ℃，而不是 99.9 ℃。
4. 重复触发评估，确认 `reached_temperature` 只有一条。
5. 进入 R201-50，在陈化起点、20 min、40 min 写入 CH2 样本。
6. 再次评估，确认生成两个 `aging_temperature_checkpoint`。
7. 重复评估，确认检查点仍为两条。
8. 把相邻样本间隔设置为超过 `telemetry_gap_threshold_ms`，确认详情与 PDF 显示缺口。

## 边界

- 未绑定 `reaction_temp` 时不得显示来源不明的自动到温。
- 缺少 `reaction_temp_min_c/max_c` 或 `reach_temp_consecutive_samples` 时只显示“未配置”，不得自行硬编码并放行。
- `run_id=NULL` 的连续监测样本与指定 `run_id` 的样本都应按绑定窗口查询。
- 自动事件必须为 `source_type=derived`、`actor=system`，并保留所用样本 ID。

## 通过标准

- 指定通道值、到温事件、检查点事件和 PDF 曲线一致。
- 重复评估不重复写事件。
- 数据缺口不被静默忽略，也不会修改原始样本。
