> 文件性质:注射泵技术标准 ｜ 编号:Q/B-LF-RDB-1201

> 传输模式:Modbus **RTU**

## 一、指令(功能码)

雷弗系列注射泵硬件接口采用 RS485,支持 MODBUS 协议。通过此协议可方便地与各种工业设备组成集中监控、集散控制,支持各种工业控制器(人机界面、工控机、计算机、PLC 等)。Modbus 通信协议栈包括两层:Modbus 应用层协议和网络层。**本公司产品均采用 RTU 模式传输。**

目前支持的指令如下("泵使用"列标记的是注射泵实际用到的指令,即原文红色字体):

| 功能码 | 名称 | 作用 | 泵使用 |
|---|---|---|:---:|
| 0x01 | 读线圈状态 | 取得一组逻辑线圈的当前状态(ON/OFF) | |
| 0x02 | 读输入状态 | 取得一组开关输入的当前状态(ON/OFF) | |
| **0x03** | 读保持寄存器 | 在一个或多个保持寄存器中取得当前的二进制值 | ✅ |
| **0x04** | 读输入寄存器 | 在一个或多个输入寄存器中取得当前的二进制值 | ✅ |
| 0x05 | 写单个线圈 | 强置一个逻辑线圈的通断状态 | |
| **0x06** | 写单个寄存器 | 把具体二进值装入一个保持寄存器 | ✅ |
| 0x0F | 写多个线圈 | 强置一串连续逻辑线圈的通断 | |
| **0x10** | 写多个寄存器 | 把具体的二进制值装入一串连续的保持寄存器 | ✅ |
| 0x11 | 报告从结点 ID | 可使主机判断编址从机的类型及该从机运行指示灯的状态 | |
| **0x17** | 读/写多个寄存器 | 同时读写多个保持寄存器 | ✅ |

## 二、协议

### 1. 协议模型

主机查询信息与从机响应信息结构相同,均由以下部分构成:**设备地址 → 功能代码 → 8 位数据字节 → 错误校验**。主机发出查询,从机返回响应。

### 2. 每个字节的格式

| 项目 | 值 |
|---|---|
| 编码系统 | 8 位二进制,十六进制 0-9、A-F |
| 数据位 | 1 起始位 + 8 位数据(低位先送) |
| 校验 | 偶校验 1 位 |
| 停止位 | 1 位 |
| 错误校验区 | 循环冗余校验(CRC) |

### 3. 信息帧格式(RTU)

信息开始至少需要有 3.5 个字符的静止时间(下图 T1-T2-T3-T4),依据波特率可计算该静止时间。接着第一个区为设备地址,各区允许发送的字符均为十六进制 0-9、A-F。网络上的设备连续监测总线信息(含静止时间),接收到第一个地址数据时每台设备立即解码以判断是否是自己的地址。发送完最后一个字符后,同样有 3.5 个字符的静止时间,然后才能发送新信息。整个信息必须连续发送。

- 若发送帧期间出现 **大于 1.5 个字符** 的静止时间,接收设备会刷新丢弃不完整信息,并假设下一个字节为地址。
- 若两帧之间 **无 3.5 个字符** 的静止时间,会因 CRC 校验码无效而产生错误。

**RTU 信息帧结构:**

| 开始 | 地址 | 功能 | 数据 | 校验 | 终止 |
|---|---|---|---|---|---|
| T1-T2-T3-T4 | 8 Bit | 8 Bit | N×8 Bit | 16 Bit(CRC) | T1-T2-T3-T4 |

#### 3.1 地址设置

信息地址为 8 位(RTU),有效从机地址范围 **0–247**(十进制),各从机寻址范围为 **1–247**。主机把从机地址放入信息帧地址区寻址;从机响应时把自己的地址放入响应地址区。**地址 0 为广播地址**,所有从机均能识别。

#### 3.2 功能码设置

功能代码为 8 位(RTU),有效码范围 1–225(十进制)。主机向从机发送信息时,功能代码说明应执行的动作(如读一组寄存器数据)。从机响应时,功能代码可说明正常响应或出错(不正常响应);正常响应时从机简单返回原始功能代码。

#### 3.3 数据区的内容

数据区由 2 个十六进制数据位组成,数据范围 00–FF,由一个 RTU 字符构成。主机发送的数据中包含从机执行功能代码所需的请求动作(如寄存器地址、处理对象数目、实际数据字节数等)。

- 例:主机以功能码 03 请求读一组寄存器 → 数据区规定寄存器起始地址及数量。
- 例:主机以功能码 10H 向从机写一组寄存器 → 数据区规定写入起始地址、寄存器数量、数据字节数及要写入的数据。

若无错误,从机响应信息中会包含请求数据。

#### 3.4 错误校验

错误校验码为一个 16 位值(2 个 8 位字节),对信息内容执行 CRC 校验得到。CRC 校验位于信息帧最后,**先送低位字节,后送高位字节**,所以 CRC 码的高位字节是最后被传送的。

### 4. 串行传送信息(位序)

标准传送中,每个字符/字节按从左向右次序传送:最低有效位(LSB)在前,最高有效位(MSB)在后。

- **带奇偶校验:** Start → 1 2 3 4 5 6 7 8 → Par → Stop
- **无奇偶校验:** Start → 1 2 3 4 5 6 7 8 → Stop → Stop

## 8. RS485 硬件接口(DB15 针)

> 📌 原文此节标题写作"雷弗蠕动泵的 RS485 硬件接口",但本文件为注射泵协议,按原文保留;接线方式通用。

RS485 通讯用到 DB15 的引脚:**4 脚 +24V_W、2 脚 B、3 脚 A、8 脚 COM**;B/A 分别接对端设备的 B/A。

**(1) 外供电**
将外部 +24V 电源的正端与 4 脚 +24_W 连接,负端与 8 脚 COM 连接即可。

**(2) 内供电**
将 DB15 的 10 脚 +12V 与 4 脚 +24_W 连接,11 脚 GND 与 8 脚 COM 连接即可。

> 交叉参考:TYD02 产品说明书中 DB15 的 10 脚标注为"内部 +24V 电源输出端";此协议文档标注为"+12V"。两处口径不一致,实际接线电压请以设备铭牌/实测为准。

## 附:开发速查(自动轮询建议)

面向"读取并导出运行数据"的场景,可按寄存器分区规划轮询:

- **实时状态(高频轮询,0x04 读输入寄存器):** 1000 内部温度、1002 注入转速、1004 当前运行步数、1008 当前运行时间、1032 累计液量(+1034 单位)、1035 消耗液量、1038 剩余液量、1041 抽取转速、1043 消耗时间、1045 剩余时间、1047 报警状态。这些是运行级/时序采样的主要数据源。
- **配置/工况(低频或按需,0x03 读保持寄存器):** 4017 工作模式、4021 注射器编号、4028 从机地址、4029 波特率、1052/1054 最大最小流速、33–36 各模式三组参数。
- **控制写入(0x06/0x10):** 4126 运行状态(启停)、4024 暂停、4025 分配状态、4023 运动方向、3001/3002 快速注入/抽取。
- **累计量(掉电保存,0x03):** 4800 运行总次数、4802 运行总步数(≈累计液量)。
- **字节序注意:** 4 字节 Float / Long 跨 2 个寄存器,CRC 为低字节在前;实际字寄存器内/寄存器间字节序需按设备实测确定(4127 可切换"计算机/PLC"模式,可能影响字序),建议先用已知值(如 1018 "LeadFluid"、1023 "TYD01")标定解析方式。
